## Claim boundary

This ledger records M2 behaviour. Every `Must` row below is now `Verified`
against the transition rule at the end of this document: each names a frozen
contract, a committed fixture, a recorded tolerance, and a test that reproduces
it. Gate `P6` evidence is in [`GATE_P6_EVIDENCE.md`](GATE_P6_EVIDENCE.md).

What `Verified` does **not** mean: that a capability outside this table works,
that a second artifact pair is supported, or that any input format other than
PNG is accepted. Verification is per row and per artifact, never by extension.

[M2_CONTRACT_COVERAGE.md](M2_CONTRACT_COVERAGE.md) maps each Must row to its
current contract authority, implementation evidence, and start gate. It records
the absence of unsupported layers as deliberately as implemented ones.

All inventory rows outside this table remain M7 work under
`SCOPE_CLASSIFICATION.md`.

| Difference | Reason | Public wording required |
|---|---|---|
| No modern PaddleX wrapper/pipeline API | The exact PaddleX resolver is not pinned for the inspected upstream checkout. | "Classic native OCR slice"; never "PaddleX wrapper compatible." |

This row records what M2 shipped, not the current position. | "Orientation/unwarping are not supported in M2." |

## Verification transition rule

Before any row changes from `Planned`, link it to a concrete contract, model
manifest, fixture directory, tolerance record, test command/result, and any
approved intentional difference. A model name alone is never compatibility
evidence.

### What every verified row must state

`COMP-002` closes on this list. Each row above names, in its status cell:

1. **The module** that implements it, by path.
2. **The contract document** the behaviour was frozen into.
3. **The fixture** the claim is checked against, or an explicit "no artifact".
4. **The decision** that governs it, where one applies.
5. **Whether an accuracy claim is made.** Every specialized row says
   **no accuracy claim**, and that is not boilerplate: every oracle in this
   repository pins preprocessing and postprocessing. None asserts what a model
   detects. A reader should take these rows as "this port agrees with upstream
   about what to send the model and what to do with the answer".

### What this ledger deliberately does not have

A **tolerance column**. Every verified row above is either bit-identical or
carries an explicitly recorded bound in its contract — the cubic resize's, in
the two rows that inherit it. A tolerance column would invite a number where
"exact" is the actual answer, and would make the two bounded rows look like the
normal case rather than the exception.

### Audit trail

The rows were audited against the source tree on 2026-08-05, not transcribed
from the roadmap. That audit found one row asserting a capability was **absent**
when it had been delivered — "no orientation classifier or document unwarping",
now marked as recording what M2 shipped rather than the current position — and
six delivered capabilities with **no row at all**, added above. A ledger that
omits what shipped is a worse failure than one that is merely unlinked.
